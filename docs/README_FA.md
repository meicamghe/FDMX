# راهنمای فارسی FDMX

این سند معرفی پروژه، وضعیت فعلی توسعه، روش نصب و اجرا، و نحوه ساخت فایل اجرایی ویندوز (EXE) و نصب‌کننده را توضیح می‌دهد.

## FDMX چیست؟

FDMX یک برنامه دسکتاپ مدیریت دانلود است که با **Python** و **PySide6 (Qt)** ساخته شده است. برنامه برای مدیریت دانلودهای HTTP/HTTPS طراحی شده و در کنار امکانات دانلود، اتصال به مرورگر و سامانه افزونه (Plugin) نیز دارد.

نسخه فعلی شاخه توسعه:
- فایل اجرای اصلی: `FDMX_v6_36.py`
- شماره نسخه برنامه: **6.36**
- نسخه دارای ظاهر Ubuntu: فایل `ubuntu.py` (شاخه کدنویسی جداگانه و نیازمند تست مستقل)

نسخه‌های شماره‌گذاری‌شده قدیمی‌تر برای حفظ تاریخچه توسعه در مخزن باقی مانده‌اند. برای اجرای نسخه فعلی این شاخه، فایل قدیمی مثل v6.11 را اجرا نکنید؛ از `FDMX_v6_36.py` استفاده کنید.

> **وضعیت توسعه:** قابلیت‌های Plugin SDK 1.7 روی شاخه توسعه قرار گرفته‌اند، اما آخرین اجرای تست یکپارچه CI با خطا تمام شده است. بنابراین این مرحله هنوز پایدار و آماده انتشار عمومی اعلام نمی‌شود. در حال حاضر فایل نصب نهایی و نسخه Release امضاشده منتشر نشده است.

## تا این مرحله چه چیزهایی ساخته شده؟

### ۱. هسته دانلودمنیجر
- دانلود فایل از لینک‌های HTTP و HTTPS
- دانلود چنداتصالی با امکان تنظیم تعداد اتصال‌ها
- توقف موقت، ادامه، لغو و تلاش مجدد دانلود
- مدیریت وظایف و نگهداری اطلاعات دانلودها پس از بستن برنامه
- تاریخچه دانلود
- زمان‌بندی شروع دانلود
- محدودسازی سرعت انتقال
- انتخاب مسیر ذخیره‌سازی و دسته‌بندی فایل‌ها بر اساس نوع

### ۲. اتصال مرورگر
- سورس افزونه برای Chrome و Firefox
- ارسال لینک به برنامه از طریق سرویس محلی
- ارتباط از طریق آدرس Loopback یعنی `127.0.0.1:38471`

### ۳. سیستم افزونه‌ها
- Plugin Manager برای نصب، فعال/غیرفعال‌سازی، بارگذاری و حذف افزونه
- اعتبارسنجی Manifest و مجوزهای تعریف‌شده افزونه
- اجرای افزونه در پردازش جداگانه (Worker Process)
- ذخیره تنظیمات و داده اختصاصی هر افزونه
- امضای دیجیتال Ed25519 و بررسی صحت فایل‌های افزونه
- اعتماد محلی به ناشر و بررسی اثرانگشت کلید عمومی
- مخزن HTTPS برای دریافت فهرست افزونه‌ها و بسته‌ها
- به‌روزرسانی افزونه با بررسی نسخه، هش و امضای ناشر
- نگهداری نسخه‌های قبلی و امکان Rollback در SDK 1.7

نکته امنیتی: اجرای افزونه در پردازش جداگانه به معنی Sandbox امنیتی سیستم‌عامل نیست. افزونه همچنان با سطح دسترسی کاربر فعلی اجرا می‌شود؛ فقط افزونه‌های قابل اعتماد را نصب کنید.

## روش اول: نصب و اجرای مستقیم در ویندوز

### مرحله ۱: نصب Python

Python 3.11 یا 3.12 را نصب کنید. هنگام نصب، گزینه **Add Python to PATH** را فعال کنید.

### مرحله ۲: دریافت سورس پروژه

از صفحه GitHub گزینه **Code → Download ZIP** را بزنید و فایل را استخراج کنید؛ یا در PowerShell اجرا کنید:

```powershell
git clone https://github.com/meicamghe/FDMX.git
cd FDMX
```

برای دریافت همین شاخه توسعه، پس از ورود به پوشه پروژه اجرا کنید:

```powershell
git switch feature/fdmx-6.22-advanced-fingerprinting
```

### مرحله ۳: ساخت محیط مجازی و نصب پیش‌نیازها

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
python -m pip install PySide6 cryptography
```

اگر PowerShell اجازه فعال‌سازی محیط مجازی نداد، از CMD استفاده کنید:

```bat
.venv\Scripts\activate.bat
python -m pip install --upgrade pip
python -m pip install PySide6 cryptography
```

### مرحله ۴: اجرای برنامه

```powershell
python FDMX_v6_36.py
```

برای اجرای نسخه Ubuntu Theme:

```powershell
python ubuntu.py
```

## روش دوم: ساخت فایل EXE مستقل برای ویندوز

فایل EXE مستقل را می‌توان با PyInstaller ساخت. ساخت نسخه ویندوز باید روی خود ویندوز انجام شود؛ PyInstaller ابزار Cross-Compile نیست.

### ۱. آماده‌سازی ابزار ساخت

در پوشه پروژه، PowerShell را باز کنید:

```powershell
py -3.12 -m venv .build-venv
.\.build-venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
python -m pip install PySide6 cryptography pyinstaller
```

### ۲. ساخت فایل اجرایی Worker افزونه‌ها

سیستم افزونه‌ها یک پردازش کمکی جداگانه دارد. این فایل باید Console باشد تا ارتباط استاندارد JSON Lines آن خراب نشود:

```powershell
pyinstaller --noconfirm --clean --onefile --console --name fdmx_plugin_worker fdmx_plugin_host.py
```

### ۳. ساخت فایل اصلی FDMX.exe

```powershell
pyinstaller --noconfirm --clean --onefile --windowed --name FDMX --collect-all PySide6 --collect-all cryptography FDMX_v6_36.py
```

### ۴. قرار دادن Worker کنار EXE اصلی

```powershell
Copy-Item .\dist\fdmx_plugin_worker.exe .\dist\ -Force
```

ساختار خروجی باید حداقل به این شکل باشد:

```text
dist/
  FDMX.exe
  fdmx_plugin_worker.exe
```

حالا می‌توانید `dist\FDMX.exe` را اجرا کنید. فایل Worker را حذف یا از کنار برنامه جابه‌جا نکنید؛ برنامه برای اجرای افزونه‌ها به آن نیاز دارد.

### ۵. تست فایل EXE

قبل از استفاده روزمره، خروجی را روی یک ویندوز 10 یا 11 تمیز که Python روی آن نصب نیست آزمایش کنید:
- باز شدن برنامه و نمایش رابط گرافیکی
- شروع، توقف و ادامه دانلود
- ذخیره و بازیابی تاریخچه و وظایف
- ارتباط افزونه مرورگر
- باز شدن Plugin Manager
- نصب و فعال‌سازی یک افزونه نمونه

اگر PyInstaller خطای ماژول یا Qt Plugin داد، باید بر اساس متن واقعی خطا تنظیمات Build اصلاح شود. ساخته‌شدن فایل EXE به‌تنهایی به معنی سالم‌بودن نسخه نهایی نیست.

هر بار که کد SDK یا Worker تغییر می‌کند، هر دو فایل اجرایی را دوباره بسازید.

## روش سوم: ساخت فایل نصب Setup.exe

تفاوت EXE و Setup:

- **نسخه Portable:** کاربر فایل `FDMX.exe` را از داخل یک پوشه اجرا می‌کند و فایل `fdmx_plugin_worker.exe` نیز باید کنار آن باشد.
- **نسخه Installer:** فایل Setup برنامه را در مسیر نصب کپی می‌کند، میانبر Start Menu/Desktop می‌سازد و امکان حذف برنامه را فراهم می‌کند.

در حال حاضر در مخزن، اسکریپت نگهداری‌شده Inno Setup و فایل نهایی Setup.exe وجود ندارد. پس از ساخت و تست دو فایل EXE بالا:

۱. نرم‌افزار [Inno Setup](https://jrsoftware.org/isinfo.php) را نصب کنید.
۲. یک اسکریپت نصب بسازید که هر دو فایل `FDMX.exe` و `fdmx_plugin_worker.exe` را در یک پوشه نصب قرار دهد.
۳. میانبر برنامه را به `FDMX.exe` وصل کنید.
۴. اسکریپت را Compile کنید تا فایل Setup.exe ساخته شود.

اطلاعات کاربر مانند تاریخچه دانلود و داده افزونه‌ها باید در پروفایل کاربر (مانند `%USERPROFILE%\.fdmx`) باقی بماند، نه داخل Program Files. نصب‌کننده نباید هنگام حذف برنامه، بدون تأیید کاربر اطلاعات شخصی را پاک کند.

تا زمانی که نصب، اجرا، به‌روزرسانی و حذف روی یک ویندوز تمیز تست نشده، Setup را نسخه انتشار نهایی در نظر نگیرید.

## اتصال افزونه مرورگر

### Chrome
۱. ابتدا FDMX را اجرا کنید.
۲. وارد `chrome://extensions` شوید.
۳. Developer mode را روشن کنید.
۴. روی **Load unpacked** بزنید.
۵. پوشه `browser-extensions/chrome` را انتخاب کنید.

### Firefox
۱. ابتدا FDMX را اجرا کنید.
۲. وارد `about:debugging#/runtime/this-firefox` شوید.
۳. گزینه **Load Temporary Add-on** را انتخاب کنید.
۴. فایل `browser-extensions/firefox/manifest.json` را انتخاب کنید.

افزونه Firefox در این روش موقت است و با بستن مرورگر حذف می‌شود؛ انتشار دائمی نیازمند امضای Mozilla است.

سرویس اتصال مرورگر فقط برای ارتباط روی همان سیستم و از طریق `127.0.0.1:38471` طراحی شده است. آن را روی شبکه عمومی یا آدرس `0.0.0.0` منتشر نکنید.

## اجرای تست‌ها

برای اجرای تست‌های سیستم افزونه‌ها از ریشه پروژه:

```powershell
python -m pip install PySide6 cryptography
python -m py_compile FDMX_v6_36.py fdmx_plugin_sdk.py fdmx_plugin_host.py fdmx_plugin_repository.py
python -m unittest discover -s tests -v
```

CI پروژه تست‌ها را روی Windows و Ubuntu با Python 3.11 و 3.12 اجرا می‌کند. آخرین اجرای تست یکپارچه SDK روی شاخه توسعه با خطا مواجه شده است؛ پیش از اعلام پایداری SDK 1.7 باید خطا بررسی و رفع شود. Workflowهای قدیمی ساخت ویندوز برای نسخه‌های قدیمی برنامه هستند و هنوز خط لوله انتشار تأییدشده برای v6.36 محسوب نمی‌شوند.

## محل ذخیره اطلاعات

تاریخچه دانلود و وظایف برنامه در پوشه `.fdmx` داخل پوشه Home کاربر نگهداری می‌شوند؛ از جمله فایل‌های `history.json` و `tasks.json`. این پوشه را از محل نصب برنامه جدا نگه دارید.
